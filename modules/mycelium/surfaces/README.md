# The Surfaces

What Joel can do with his cells, act for act, on each surface he works
from: the mycelium command, a pi session, the map and the launcher. On 24
November 2026 he asked that they stay even: "any interface i'm in should be
directly engagable to a meaningful level".

| File            | What it holds                                                |
| --------------- | ------------------------------------------------------------ |
| `acts.toml`     | the table: each act, and where each surface has it, who owes |
|                 | it and by when, or why it never will                         |
| `stays-even.py` | what `mycelium-surfaces-stay-even` runs over the table       |

An act one surface gains is added to the table with every other surface
owing it, so the check fails until each has it, owes it by a time or
waives it. Where a surface lists its acts in a file, the table's `offered`
entries read that list, and an act there the table doesn't name fails, so
a gained act can't go unseen. Two lists are read: the launcher's session
row, its `verb:agent:` verbs, though not its verbs under other ids such
as Carry Back, and the acts a cell's drawer on the map offers, by their
words' keys in `site/acts.ts`. The command and a pi session
list theirs nowhere core.nix reads, so an act they gain is added by hand.

Each act names the one way to it, the node's call or the files every
surface reads, so a surface bringing it calls what the others call. The
log lists what is still owed, soonest first; a due time passing is read
by people and the dates cell, since the check has no clock.

A has proves its words are where it says, not that the surface's code
offers the act, which the surfaces' own tests prove, nor that an act is
worded alike on each surface. A pi tool is taken by its name, with a note
saying how it does the act, since the harness that holds the tools isn't
an input of core.nix.
