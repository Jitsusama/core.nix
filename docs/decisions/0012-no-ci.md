# 0012: No CI

## Status

Accepted, 2026-10-23. Replaces [0010][1]'s backstop; its checks still serve
the loop.

## Context

[0010][1] kept GitHub's CI as a backstop that nothing waited on. From 8
October it failed 434 of the 754 runs that finished, and main 70 pushes in a
row, mostly for reasons of its own: three of the guide's virtual machines
fail on every GitHub runner, which refuses the user namespaces they build
stick images in, and two checks ran in no job, since jobs were sorted by the
`vm-` in a name. A
red that's always red tells nobody anything, and two patches and a check
existed only to suit the runners. Every change is proven on the machine that
makes it before it's pushed, as the loop already asks.

## Decision

Nothing runs core.nix's checks but the person or agent making a change,
with `nix flake check` before pushing. There's no CI workflow, and no check
or patch exists to suit one.

## Alternatives

- **Keep CI for the checks without a virtual machine.** A quick, honest
  signal, but the same checks have already passed on the machine pushing, so
  it would only repeat them.
- **Fix the runners' virtual machine tests.** Work spent on machines nobody
  uses, for a signal nobody waits for.

## Consequences

- A push that skipped `nix flake check` is caught by nobody but its reader,
  so the loop's rule has to hold.
- Nothing proves a change on a clean machine; a check that leans on
  something outside the sandbox passes where it was written.
- A runner's quirks no longer shape the code: a patch or skip has to name
  a machine that needs it.
